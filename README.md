Я **Егор Овечкин**. Мне интересен не отдельный экран или эндпоинт, а весь путь продукта: сценарий пользователя → модель данных → ошибки → тесты → развёртывание → документация.

Поэтому мои проекты сильно отличаются внешне, но отвечают на один вопрос:

> **Как сделать сложную вещь понятной, надёжной и пригодной для реального использования?**

Сейчас я отвечаю на него в трёх масштабах.

## 🪐 Система: [Saturn](https://github.com/egkodin/saturn)

**Социальная платформа, где люди и ИИ работают с публикациями, сообщениями и документами.**

Здесь я учусь держать в голове продукт целиком: авторизацию и права доступа, PostgreSQL и миграции, чат и WebSocket, уведомления, поиск, модерацию, историю версий, Docker-инфраструктуру и тесты.

```text
FastAPI · PostgreSQL · SQLAlchemy · Alembic · WebSocket · Docker · nginx · pytest
```

Не просто набор API: система с состоянием, ошибками, пользовательскими ожиданиями и жизненным циклом данных.

[Посмотреть архитектуру и запуск →](https://github.com/egkodin/saturn)

## 🎵 Инструмент: [Taglet](https://github.com/egkodin/taglet)

**Нативный редактор ID3v2-метаданных для MP3 — без аккаунтов, облака и webview.**

Taglet работает с файлами локально, создаёт резервную копию до первой записи, защищает несохранённые изменения и аккуратно обрабатывает обложки и метаданные.

```text
Rust · eframe/egui · lofty · Cargo · local-first
```

Этот проект для меня — практика тихого, предсказуемого софта: приложение не должно требовать доверия, которого оно не заслужило.

[Открыть Taglet →](https://github.com/egkodin/taglet)

## ✦ Метаслой: [Asterframe](https://github.com/egkodin/asterframe)

**Дизайн-направление для ИИ-агентов разработки: один скилл, 27 команд и 44 детерминированных правила.**

Asterframe помогает агентам не скатываться в одинаковые интерфейсы: сначала понять контекст продукта, затем выбрать подходящий процесс, сохранить поведение и доступность, проверить результат в браузере и прогнать автоматические проверки.

```text
Agent skills · Node.js · Python · UI/UX intelligence · browser iteration
```

Здесь я превращаю неявное инженерное и дизайнерское суждение в воспроизводимый процесс, которым может пользоваться другой разработчик или агент.

[Изучить Asterframe →](https://github.com/egkodin/asterframe)

## Код у меня начинается не с кода

**Сначала контекст.** Кто пользуется продуктом, какую задачу решает и какие ограничения уже существуют?

**Затем сценарий.** Что должно произойти в нормальном случае — и что увидит человек, когда всё пойдёт не так?

**Потом данные.** Валидация, миграции, резервные копии и понятные ошибки — не техническое послесловие, а часть продукта.

**И только потом инструменты.** Выбираю технологию под задачу, а не задачу под красивый список технологий.
